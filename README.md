# 高并发闪购商城

面向秒杀场景的高并发商城 Demo：商品列表 / 详情 / 下单 / 支付全链路，重点演示**如何在高并发下做到库存零超卖**。

> **零依赖**：只用 Node.js 内置模块，`node server.js` 即可运行。
> ⚠️ 部署沙箱不提供外部中间件，因此本 Demo 用**进程内组件等价模拟** Redis / MySQL / MQ 的语义（见下），聚焦「并发链路与正确性」，而非真实中间件运维。

## 秒杀完整链路

```
用户点击抢购
   │
   ├─ ① 令牌桶限流（按用户）        超限 → 拦截
   ├─ ② 幂等去重（一用户一商品一单） 重复 → 拦截
   │
   ├─ ③ Redis Lua 预减库存（原子）   库存 ≤ 0 → 已售罄（挡在 DB 之前，保护数据库）
   │       └ 等价 Lua：GET → 判断 >0 → DECR，单线程执行保证原子
   │
   ├─ ④ 发送下单消息到 MQ（削峰）    返回"抢购成功"
   │
   └─ ⑤ MQ 异步消费：
          数据库乐观锁扣减（UPDATE ... WHERE version=? AND stock>0）
          成功 → 生成订单
          失败 → 回滚 Redis 预减库存 + 进死信
```

## 核心实现要点

| 能力 | 实现方式 |
| --- | --- |
| **零超卖** | Redis 预减（原子）+ DB 乐观锁双重校验；压力测试页面实时校验「超卖数量 = 0」 |
| **乐观锁** | 商品库存带 `version`，CAS 更新，失败可重试（模拟 MyBatis-Plus `@Version`） |
| **MQ 削峰** | 内存队列 + 异步消费 + 重试 + 死信；下单请求秒回，落库异步完成 |
| **库存回滚** | 消费失败自动把预减的 Redis 库存加回，并记录死信 |
| **多级缓存** | L1 本地缓存（短 TTL）+ L2 远端缓存，带 L1→L2 回填，统计命中率 |
| **限流** | 令牌桶（容量 8、2/s，按用户维度） |
| **降级** | 一键切换「降级模式」：跳过 Redis 直接走 DB 乐观锁，牺牲吞吐保可用 |

## 并发压测

页面内置压测面板：选择商品与并发数（最高 5000），服务端并发模拟秒杀请求，输出：

- 成功 / 售罄 / 限流 / 重复 各计数
- Redis 库存前后值、数据库库存、生成订单数
- **超卖数量**（恒为 0 即通过）与平均响应时间

## 运行

```bash
node server.js
# 打开 http://localhost:3000
```

监听 `process.env.PORT`（默认 3000），绑定 `0.0.0.0`。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/products` | 商品列表（含 Redis / DB 库存、缓存命中标记） |
| POST | `/api/seckill` | `{productId, userId}` → 抢购结果 |
| POST | `/api/stress` | `{productId, concurrency}` → 并发压测与超卖校验 |
| GET | `/api/orders` | 订单流水 |
| GET | `/api/stats` | 请求 / 超卖 / 缓存 / MQ / 库存对账 |
| POST | `/api/mode` | `{mode: normal\|degraded}` 切换降级 |
| POST | `/api/reset` | 重置库存与统计 |
| GET | `/api/health` | 健康检查 |

## 说明

- 演示数据：4 个商品，初始库存 100 / 50 / 30 / 20。
- 真实生产环境：Redis 用 `Lua` 脚本 + 集群、MySQL 分库分表、RabbitMQ 做削峰与可靠投递；本 Demo 用进程内组件等价还原其**语义与并发正确性**，便于一键运行演示。
